# IMPLEMENTATION_CHECKLIST.md — Wang Yeul Website

## 1. 구현 목표

이 구현 체크리스트의 목표는 현재 왕열 작가 홈페이지를 `docs/DESIGN.md` 기준에 맞게 순차적으로 정리하는 것이다.

최종 목표는 다음과 같다.

- 작품 중심 온라인 미술관형 홈페이지로 재구성
- 작가 소개보다 작품 감상이 먼저 시작되는 구조 확립
- 갤러리와 작품 상세 경험을 사이트의 중심으로 승격
- 전시, 소장처, 문의를 기록형 아카이브 흐름 안에서 정리
- 모바일에서도 같은 위계와 분위기 유지

이 문서는 구현 순서와 검수 기준을 정리하는 문서이며, 실제 코드 변경 전에 기준을 고정하는 용도다.

---

## 2. 수정 전 안전 원칙

- 사이트 코드를 한 번에 대규모로 바꾸지 않는다.
- 각 Phase는 독립적으로 검수 가능한 단위로 나눈다.
- 한 번에 `index.html`, `css`, `js`, `data`를 모두 뒤엎지 않는다.
- 공개 화면에서 보이는 문제를 먼저 해결하고, 구조 개편은 그 다음에 진행한다.
- 기존 데이터 구조 `data/artworks.json` 과 카테고리 키 `2jung`, `2026`, `blue`, `ink`, `red` 는 유지한다.
- 작품 이미지 경로 규칙과 JSON 구조는 구현 중 임의로 바꾸지 않는다.
- Phase별 완료 후 브라우저에서 실제 화면을 확인한다.
- 로딩/관리자 문구 제거, 메뉴 노출 조건, 필터 동작, 모바일 레이아웃은 반드시 눈으로 검수한다.

---

## 3. Phase 1 범위

Phase 1은 공개 화면의 신뢰도와 첫인상 문제를 해결하는 단계다.

핵심 작업:

- 공개 화면의 관리자 문구 제거
- 공개 화면의 로딩 문구 최소화 또는 비노출 처리
- 미완성 상태 문구 정리
- Video 데이터가 없으면 메뉴와 섹션 숨김
- Hero 다음에 `Selected Works` 배치
- 색상과 타이포그래피를 `DESIGN.md` 기준으로 정리
- 작품 갤러리의 쇼핑몰 카드 느낌 완화

구체 작업:

- `등록된 영상이 없습니다`
- `관리자 페이지에서 영상을 추가해 주세요`
- `정확한 전시 횟수는 ... 업데이트 바랍니다`
- `작품을 불러오는 중...`

위와 같은 공개용 부적합 문구를 제거하거나, 조건부 숨김 처리한다.

- Hero 직후 섹션 순서를 재조정해 `Selected Works`가 먼저 보이게 한다.
- 기존 갤러리 카드의 경계, 그림자, 버튼성 인상을 약화한다.
- 기본 색상과 텍스트 위계를 `warm ivory / ink black / muted red` 방향으로 맞춘다.

Phase 1 완료 조건:

- 첫 화면이 작가 소개보다 작품 중심으로 보인다.
- 운영 문구가 공개 화면에 남아 있지 않다.
- Video 데이터가 없을 때 빈 섹션이 보이지 않는다.
- 갤러리가 더 이상 상품 카드 그리드처럼 보이지 않는다.

---

## 4. Phase 2 범위

Phase 2는 작품 감상 경험 자체를 개선하는 단계다.

핵심 작업:

- 작품 상세 페이지 또는 모달 개선
- 큰 이미지 감상 구조 정비
- 이전/다음 작품 이동
- 작품 문의 연결
- 모바일 작품 감상 개선

구체 작업:

- 현재 라이트박스 또는 상세 뷰 구조를 도록형 구조로 재정리
- 큰 대표 이미지 우선 노출
- 제목, 연도, 재료, 크기, 시리즈 정보를 정리된 메타데이터 블록으로 구성
- 이전/다음 작품 이동은 조용한 내비게이션으로 제공
- 작품 문의는 공격적인 CTA가 아니라 조용한 링크나 버튼으로 제공
- 모바일에서 이미지와 메타데이터가 자연스럽게 이어지도록 정리

Phase 2 완료 조건:

- 작품 상세가 쇼핑몰 상품 상세처럼 보이지 않는다.
- 작품 이미지를 충분한 크기로 감상할 수 있다.
- 이전/다음 이동이 자연스럽다.
- 문의 연결은 존재하지만 전면으로 튀지 않는다.
- 모바일에서도 작품 감상이 불편하지 않다.

---

## 5. Phase 3 범위

Phase 3은 하위 정보 구조를 아카이브형으로 정리하는 단계다.

핵심 작업:

- Artist 섹션 정리
- Exhibitions 연도형 아카이브 정리
- Collections 정리
- Contact 흐름 정리
- 전체 반응형 최종 점검

구체 작업:

- Artist 섹션을 `statement` 와 `profile` 역할로 분리
- Exhibitions를 단순 나열이 아니라 연도 중심 기록 구조로 재정리
- Collections를 기관/소장처 정보 중심으로 더 정돈
- Contact를 판매형 폼이 아니라 공식 문의 창구처럼 정리
- 전체 페이지의 데스크톱/태블릿/모바일 반응형 재검수

Phase 3 완료 조건:

- Artist, Exhibitions, Collections, Contact가 모두 작품 중심 흐름을 방해하지 않는다.
- 전시 이력은 기록 문서처럼 읽힌다.
- 모바일과 데스크톱 모두 시각 위계가 안정적이다.

Phase 1 예상 파일:

- `index.html`
- `css/style.css`
- `js/main.js`

Phase 2 예상 파일:

- `js/main.js`
- `css/style.css`
- 필요 시 `index.html`

Phase 3 예상 파일:

- `index.html`
- `css/style.css`
- `js/main.js`

참고 파일:

- `docs/DESIGN.md`
- `docs/lazyweb-reference.md`
- `data/artworks.json`

주의:

- `data/artworks.json` 구조는 현재 규칙을 유지하는 전제로 접근한다.
- 이미지 폴더 구조와 카테고리 키는 구현 중 임의 변경하지 않는다.

## 7. 금지 작업

- `index.html`, `css`, `js`를 한 번에 전면 재작성
- 기존 갤러리 데이터 구조를 이유 없이 변경
- 카테고리 키 `2jung`, `2026`, `blue`, `ink`, `red` 변경
- 작품명 표시 규칙 변경
- 쇼핑몰형 가격/배지/강한 CTA 추가
- SaaS landing page 느낌 추가
- dashboard UI 도입
- ecommerce product grid 강화
- 강한 gradient 적용
- glassmorphism 도입
- 과한 애니메이션 추가
- 작품보다 UI가 먼저 보이는 구조 변경
- 관리자/운영자용 내부 문구를 공개 화면에 남기는 작업

## 8. 검수 기준

각 Phase 완료 후 아래 기준으로 검수한다.

공통 검수:

- 작품이 여전히 첫 인상인가
- UI가 작품보다 튀지 않는가
- 색상과 타이포가 `DESIGN.md`의 톤과 맞는가
- 운영 문구, 빈 섹션, 미완성 상태가 보이지 않는가

Phase 1 검수:

- Hero 다음에 `Selected Works`가 오는가
- Video 데이터가 없을 때 메뉴와 섹션이 숨겨지는가
- 갤러리가 비상업적 인상으로 정리됐는가

Phase 2 검수:

- 작품 상세에서 큰 이미지가 중심인가
- 메타데이터가 과하지 않고 읽기 쉬운가
- 이전/다음 이동이 자연스러운가
- 모바일 작품 감상이 개선됐는가

Phase 3 검수:

- Artist / Exhibitions / Collections / Contact가 기록형 구조로 정리됐는가
- Exhibitions가 연도 중심 아카이브처럼 읽히는가
- 전체 반응형 구조가 안정적인가

최종 검수 질문:

- 이 화면이 작가 사이트인가, 아니면 서비스 랜딩페이지처럼 보이는가
- 이 화면이 온라인 미술관처럼 조용한가
- 이 화면에서 가장 먼저 보이는 것이 작품인가

---

## 9. 롤백 기준

아래 상황이 발생하면 해당 Phase의 변경을 롤백하거나 재작업한다.

- 작품보다 UI가 먼저 보이게 됨
- Hero가 다시 홍보형 랜딩페이지처럼 보임
- 갤러리가 상품 카드나 쇼핑몰처럼 보임
- 작품 상세가 상품 상세 페이지처럼 변질됨
- Artist / Exhibitions / Contact가 작품 흐름을 방해함
- 모바일에서 이미지보다 텍스트가 먼저 밀려옴
- Video 숨김, 필터, 라이트박스, 메뉴 등 기존 기능이 깨짐
- `data/artworks.json` 기반 표시 로직이 깨짐
- 카테고리 필터가 동작하지 않음

롤백 원칙:

- 마지막으로 안정적으로 보였던 Phase 단위까지 되돌린다.
- 미완성 상태를 남긴 채 다음 Phase로 넘어가지 않는다.
- 시각 개선보다 기능 정상 동작을 우선한다.
